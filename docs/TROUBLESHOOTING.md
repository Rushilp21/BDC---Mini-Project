# Troubleshooting

* **Docker pipe missing / cannot connect:** start Docker Desktop in Linux-container mode and wait for `docker info` to succeed. WSL2 must be enabled on Windows. An installed Docker CLI alone is insufficient. This implementation session encountered Docker Desktop's `initializing Inference manager ... dockerInference: The file cannot be accessed by the system` startup crash. It is an engine/runtime problem, not a Kafka response. Restart/repair Docker using its supported UI; preserve existing volumes. Do not factory-reset unrelated user data to run this project.
* **Spark Java gateway exits:** use Java 17, confirm `java -version`, `JAVA_HOME`, and architecture. Android Studio's bundled Java 21 is outside the selected Spark 3.5 compatibility set. Containers include Java 17. Host Python executable must be consistent with `PYSPARK_PYTHON`.
* **Windows winutils / NativeIO / Parquet write:** prefer Docker Linux containers or WSL2. Do not download arbitrary untrusted `winutils.exe` files. Java presence alone may not make Hadoop's Windows filesystem layer usable.
* **Cannot find Kafka data source / connector classes:** launch via `spark-submit --packages org.apache.spark:spark-sql-kafka-0-10_2.12:3.5.7`. Connector version and Scala suffix must match Spark. Docker image resolves JARs at build time. Maven Central must be reachable during first build. Inspect `docker compose logs stream` for Ivy resolution errors.
* **Kafka bootstrap connects but metadata fails:** advertised listeners must match the caller. Host clients use localhost:9092, Compose uses kafka:29092. A container's localhost is itself, not the backend or broker. The controller port is not a producer bootstrap listener.
* **Topic missing:** inspect `docker compose logs topic`; run `docker compose run --rm topic`. It uses `--if-not-exists` and one partition/replica.
* **Stream HTTP 403:** backend and Spark `ADMIN_TOKEN` values differ. Recreate both with matching environment; enter the same token in the dashboard. Prefix queries do not require this token.
* **Stream HTTP 409:** one checkpoint batch identity was reused with different payload. Inspect the checkpoint lifecycle and stop competing consumers. Do not edit applied-batch identities to hide corruption. An isolated reset creates a new stream UUID.
* **No stream update:** start services first; inspect producer error and Spark heartbeat. Producer deliberately delays ten seconds and emits one event, then stops. The consumer remains running. Inspect actual applied batches. Kafka TCP reachability alone proves no successful processing.
* **Failed batch with lost acknowledgement:** restart `docker compose restart stream`; Spark retries uncommitted checkpoint progress, and SQLite batch checks prevent duplicate application. Existing records use max count and do not get duplicate fingerprints.
* **Empty dashboard / API errors:** confirm backend health at localhost:8000/api/health, valid admin token and same-origin `/api` proxy. Frontend dev port may change if 5173 is occupied; use the printed Vite URL.
* **Web Crypto undefined:** use localhost or HTTPS. Remote insecure HTTP does not provide the required secure browser context.
* **Real acquisition unavailable:** retry bounded script; no full corpus fallback is attempted. Generate fixtures for explicitly synthetic tests, and report real integration as incomplete. Download provenance is created only after a complete bounded acquisition.
* **Long initial build:** PySpark is roughly 317 MB, plus JRE and Maven dependencies. Download before the demonstration. No Python-only processing fallback is hidden behind the Spark label.
* **Import read failure:** job displays an error. It is not included as an arbitrary number of rejected rows. Check UTF-8 format, JSON array vs JSONL, required counts and full 40-character hashes. Sources are caller-supplied provenance, not automatically certified as real HIBP data.
* **Unavailable filters:** exact storage remains queryable. Rebuild from Filter Comparison; inspect failed jobs. Never infer absence from a known incomplete index.
* **Port collision:** change only the loopback side of the Compose port binding and use that URL; preserve internal backend port 8000 and Kafka listener definitions unless updating corresponding clients.
* **WSL SQLite `unable to open database file`:** keep the live WAL database on a Linux filesystem and avoid opening it simultaneously from Windows. The prepared WSL runtime uses `SQLITE_PATH=/opt/bdc-state/breach.sqlite`; imports/Parquet can remain on the Windows mount. A one-time offline migration helper preserves and checks the main database. Do not run that helper over an existing target or while a source WAL remains active.
